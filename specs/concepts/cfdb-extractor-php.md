# Spec: cfdb-extractor-php

PHP `LanguageProducer` MVP (RFC-041 Phase 2 / issue #264). Walks a Composer-style PHP project via tree-sitter-php and emits the v0.1 cfdb fact set onto the existing closed-set schema vocabulary in `cfdb-core::schema::labels` — no new `:Item.kind` values are introduced (Published Language invariant per RFC-041 §4). Operationally a cfdb-monolith member crate per `.cfdb/concepts/cfdb.toml`; gated behind `lang-php` in `cfdb-cli` so default builds drop the entire tree-sitter dep tree.

## PhpProducer

Reference implementation of `cfdb_lang::LanguageProducer` for PHP workspaces. `name()` returns `"php"` (matching the `lang-php` Cargo feature on `cfdb-cli`). `detect()` is the marker-file check `workspace_root.join("composer.json").is_file()` — Composer's PSR-4 manifest is the canonical PHP project marker. `produce()` walks `**/*.php` under workspace_root (skipping `vendor/`), parses each file via tree-sitter-php's `LANGUAGE_PHP` constant (0.23 ABI shared with `cfdb-extractor-ts`), and emits sorted-canonical `(Vec<Node>, Vec<Edge>)`. Any tree-sitter parse failure or I/O error wraps to `LanguageError::Parse { producer: "php", ... }` / `LanguageError::Io`. Schema mapping decision (preserves the closed-set invariant; documented in the crate-root doc + `Cargo.toml` header): PHP `namespace` → `:Module` node; PHP `class` / `interface` / `trait` → `:Item { kind: "trait", php_construct: <ast-kind> }` and PHP `enum` → `:Item { kind: "enum", php_construct: "enum_declaration" }` (the `php_construct` prop is the disambiguation seam for cypher queries that need to distinguish them; `"enum"` is already inside `cfdb-041-language-backend-trait#4`'s closed kind set, so no kind, no label and no schema version is added — `cfdb-045-polyglot-relationship-edges#3.2`, amended 2026-09-07); PHP `method` / `function` → `:Item { kind: "fn" }`, a method declared in an enum body carrying the enclosing enum's qname exactly as a class method does (`cfdb-045-polyglot-relationship-edges#2`, `#3.4` D4); PHP `const` → `:Item { kind: "const" }` (reserved; MVP doesn't yet emit class constants). Defined at `crates/cfdb-extractor-php/src/lib.rs:75`.

Name resolution precedes D2. The target of an `implements` clause is resolved the way PHP resolves a name: a fully qualified name stands as written; an unqualified or qualified name goes first through the file's `use` imports — plain, aliased (`use A\B as C`) and grouped (`use A\{B, C}`) — and otherwise through the current namespace; only the resolved qualified name is matched against the in-workspace item set, and an `IMPLEMENTS` edge exists iff that match succeeds (cfdb-045 §3.2, D2). The callee of a scoped call resolves through the same table before the `CALLS` decision of cfdb-045 §3.4. An `implements` clause on an enum is read as one on a class is, keyed on the clause and not on what declares it (cfdb-045 §3.2, 45-A). A name that resolves outside the workspace yields no edge and no placeholder, as D2 orders; a name resolved to the current namespace when a `use` import names it is a producer defect, never a closed-world case.

An enum's cases yield no `:Item`. No clause admits a PHP variant — neither `cfdb-045-polyglot-relationship-edges` nor `cfdb-041-language-backend-trait` carries one, and the `:Variant` label is the Rust producer's — and `cfdb-041-language-backend-trait#4.5` gates the widening behind its own RFC. The silence is declared here rather than left to be read off an empty result: a rule reaching for a case's name finds nothing because nothing is emitted, not because the walk failed.
